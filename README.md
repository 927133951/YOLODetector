# CCTools — YOLO 实时检测与跟随辅助工具

基于 YOLO 模型的屏幕实时目标检测工具：GPU 直通零拷贝管线捕获屏幕 → TensorRT FP16 推理 → 500Hz 控制线程驱动鼠标跟随，附带实时预览与可视化调参界面。

## 功能特性

### 检测与推理
- **GPU 直通零拷贝管线**：屏幕捕获的 D3D11 纹理通过共享句柄直接送入 CUDA，全程无 CPU 回读，捕获→推理链路延迟极低
- **TensorRT FP16 加速**：ONNX 模型经 ONNX Runtime 的 TensorRT EP 加载为 FP16 引擎，首次运行自动编译并缓存（约 1~3 分钟），之后秒级启动
- **捕获区域自动匹配**：检测区域自动锁定为模型输入尺寸（模型按该尺度训练，其他尺寸会尺度失配）
- **检测帧率可调**：60~240 FPS，多应用共享 GPU 时建议 ≤110
- **延迟补偿**：目标横移时按画面滞后时长自动外推超前补偿（可自动或手动）

### 跟随控制
- **500Hz 独立控制线程**：与检测解耦，控制周期 2ms
- **双控制后端**：罗技驱动级 DLL（1:1 精确，不受系统指针加速影响）/ SendInput 系统级模拟
- **在线增益自校准**：自动标定"鼠标 count → 屏幕像素"映射，中位数滤波防单帧毒样本
- **亚像素累加 + 在途补偿 + 前馈通道**：消除整数取整卡顿、防止过冲震荡
- **收尾死区 + 跟随范围（FOV）**：防检测框抖动微颤、防远处误选目标
- **状态机**：IDLE → TRACKING → LOCKED，状态栏实时显示
- **紧急停止热键**：失控保底手段（默认 End）

### 界面与体验
- 深色主题 tkinter 界面，窗口自适应屏幕工作区，内容超出时自动出现整窗滚动条
- 实时预览窗口：检测框、准星十字、跟随范围圈、锁定判定圈、收尾死区、参数状态行、推理分段耗时行
- 日志支持鼠标选中 Ctrl+C 复制、右键菜单（复制选中/复制全部/清空）
- **推理运行中自动锁定**"选择模型/显示器/捕获方式"，须停止推理才能修改（避免竞态）
- **窗口隐形（默认行为，无需配置）**：主界面与预览窗口均不进任务栏/Alt-Tab；预览窗口对截图录屏软件同样不可见
- 防截屏：本窗口与预览窗口对微信/QQ/OBS 等截图录屏软件不可见
- 全部参数持久化（exe 旁 `cctools_settings.json`），悬停控件有详细调参说明气泡

### 快捷键一览

| 按键 | 功能 |
|------|------|
| 鼠标侧键 X2（可改） | 按住启用跟随辅助 |

### 线程模型

| 线程 | 职责 | 周期 |
|------|------|------|
| 主线程 | tkinter GUI + 状态轮询 | 200ms |
| 捕获-推理线程 | 抓帧 → GPU推理 → 选目标 → 发布状态快照 | 检测帧率上限内 |
| 控制线程 | 消费目标快照 → 控制律 → 鼠标位移 | 500Hz |
| 预览线程 | 帧回读(限频60Hz) + 辅助信息叠加渲染 | 120FPS 重绘节流 |
| 模型加载线程 | TRT 会话构建 | 一次性 |

线程间通过带锁状态快照（`_aim`）通信：检测线程发布，控制线程消费，快照龄期 >0.2s 自动判为无目标（防陈旧目标拖拽）。

## 核心技术

### GPU 直通零拷贝管线
屏幕捕获产出 D3D11 纹理 → `IDXGIResource` 取共享句柄 → CUDA `cudaExternalMemory` 映射 → 预处理在 GPU 上完成 → TensorRT enqueue。传统方案的 CPU 回读（`CopyResource` → `Map` → numpy）完全消除，链路节省 3~8ms。

### 捕获后端
- **WGC**（Windows Graphics Capture）：Win10 1903+ 官方捕获 API，帧到达回调式，延迟最低
- **DXGI Desktop Duplication**：传统复制链路，兼容性备胎
- 运行中捕获异常自动互切重启；显示器切换/捕获方式切换需停止推理后操作

### 控制律
比例步进 + 亚像素累加（消除末段整数取整卡死）+ 在途位移衰减（防重复发力）+ 速度前馈（速度匹配通道）+ 收尾死区。所有步进按**测量周期**（画面真正变化的间隔）折算，避免按推理 tick 折算造成等效死拍震荡。

### 推理耗时分布（实测 RTX 3080, 640 e2e 模型, TRT FP16）
| 分段 | 耗时 | 说明 |
|------|------|------|
| TRT 推理 | 2.1~3.6ms（随 GPU boost 波动） | GPU-bound，占 87%+ |
| 预处理 stage | ~0.3ms | 映射/线性化/内核/同步 |
| 输出拷贝 | ~0.014ms | 可忽略 |
| 解码 | ~0.09ms | 可忽略 |

Python 编排开销合计 <0.5ms/帧，管线能力 250~450fps，远超 240fps 上限——**瓶颈是 GPU 推理本身，不是 Python 层**。实测结论：TRT `builder_optimization_level=5` 无真实收益（此前"快 30%"是 GPU 冷启动顺序假象）；CUDA Graph 与 IOBinding 组合在本 ORT 版本下会返回过期输出（图重放写首次捕获的指针），禁用。预览覆盖层的分段耗时行（stage/run/copy/dec）可用于实时定位慢在哪一段。

### 窗口隐形与显隐切换
主界面与预览窗口默认套 `WS_EX_TOOLWINDOW` 样式（任务栏/Alt-Tab 均不出现），Tab/Home 键边沿触发 `ShowWindow` 切换显隐。关键实现细节：cv2 HighGUI 的 `imshow` 内部每帧调 `ShowWindow(SW_SHOW)`，会把隐藏的窗口立刻顶回显示——因此预览线程在隐藏状态下跳过 `imshow`。恢复用 `SW_SHOWNA`（不激活、不抢游戏焦点）。

### 打包盲区修复（PyInstaller onedir）
`CCTools.spec` 处理了 cuda-python merged wheel 的四个动态导入盲区（静态分析均不可见）：
1. `cuda.core` dispatcher 运行时 `importlib.import_module(f".cu{major}")` → 摊平 cu13 目录真实 .py/.pyd
2. Cython pyd 在 C 层动态导入 cuda/bindings 子模块 → 摊平整个 cuda/bindings
3. frozen 下无 dist-info → `copy_metadata` 收集 4 个包元数据
4. `_linker.pyd` 初始化时导入 `cuda.pathfinder._optional_cuda_import` → hiddenimports

## 快速开始

### 方式一：打包版（推荐，其他设备开箱即用）
1. 将整个 `dist/CCTools/` 文件夹拷贝到目标设备（**必须整个文件夹**，`_internal/` 内含全部运行时依赖，约 5GB）
2. 双击 `CCTools.exe` → UAC 提权确认
3. 首次启动会编译 TensorRT 引擎（约 1~3 分钟），缓存至 `C:\ProgramData\YOLO_TRT\trt_cache`，之后启动秒级
4. 在界面选择模型/显示器/捕获方式与目标类别，点击"开始推理"

### 方式二：源码运行
```bash
# 安装依赖
pip install onnxruntime-gpu cuda-python opencv-python numpy pywin32 comtypes

# 运行（管理员权限，否则游戏内控制失效）
python main.py
```

### 使用流程
1. 启动后软件自动提权 → GPU 管线就绪 → 模型加载（状态栏显示"空闲"即就绪）
2. 选择游戏所在显示器（多显示器必须选对）
3. 按需调整置信度阈值、跟随参数（悬停控件有说明气泡）
4. 开启预览窗口核对：绿色准星十字与游戏准星重合（不重合调"准星偏移"），跟随范围圈覆盖预期目标区域
5. 点击"开始推理" → 按住触发热键启用跟随辅助
6. **停止推理后**才能切换模型/显示器/捕获方式

## 参数调优指南

| 参数 | 说明 | 建议 |
|------|------|------|
| 置信度阈值 | 检测把握门槛。误检背景→调高；远处漏检→调低 | 0.45~0.55 |
| 移动比例 | 每帧消除剩余误差比例。过大→过冲画圈 | 0.3~0.45 起步 |
| 跟随范围(FOV) | 只跟随准星周围该半径内目标，0=不限制 | 30~80 |
| 收尾死区 | 误差小于该值停止移动，防框抖微颤 | 2~3 |
| 联动系数 | 鼠标 count→屏幕像素映射起点（自动校准） | 保持默认 |
| 延迟补偿 | 横移目标超前补偿。追不上→调大；冲过→调小 | 自动即可 |
| 检测帧率 | GPU 占用与新鲜度权衡。共享 GPU 建议 ≤110 | 默认 240 |
| Y轴反向 | 准星上下方向反了就勾选 | — |
| 准星偏移 | 预览里绿十字与游戏准星不重合时手动补偿 | — |

**跟随点 Y 偏移**：-0.5=框顶，0=正中心，+0.5=框底。建议 0 或略偏上沿。

**一键重置**：恢复通用稳定值（任何设备/刷新率不过冲的保守组合），不影响热键/显示器/后端/防截屏/准星偏移等个人配置。

## 日志与故障排查

| 位置 | 内容 |
|------|------|
| `<exe目录>/logs/startup.log` | 打包版全部 stdout/stderr + faulthandler 原生崩溃转储（线程栈） |
| `C:\ProgramData\YOLO_TRT\trt_cache` | TRT 引擎缓存（损坏可直接删除，下次重建） |
| `cctools_settings.json` | 用户配置（删除即恢复默认） |

**常见问题**：

1. **GPU 管线初始化失败** → 检查 NVIDIA 驱动版本；软件设计上不回退 CPU，管线失败会拒绝启动推理
2. **首次启动卡在"模型加载中"** → 正在编译 TRT 引擎，等待完成（后续启动走缓存）
3. **游戏内鼠标不动** → 必须管理员权限；控制后端选 SendInput 时需关闭系统"提高指针精确度"
4. **检测到另一块屏幕** → 显示器选择错误，停止推理后重新选择
5. **崩溃排查** → 打开 `logs/startup.log` 末尾，`Windows fatal exception` 段落即 faulthandler 崩溃转储（含崩溃线程 Python 栈）

## 已知设计决策

这些决策源于实测踩坑，改动前请阅读对应代码注释：

1. **GC 永久禁用**：循环 GC 遍历本应用的原生互操作对象（ORT/TRT 会话、CUDA 管线、WinRT/D3D 捕获包装）= 原生崩溃。faulthandler 实测 10+ 次崩溃均发生在 GC 遍历中。引用计数覆盖绝大部分回收，成环垃圾量级可忽略。
2. **GPU 失败不回退 CPU**：管线初始化失败直接拒绝启动推理，静默回退会造成"看似正常实际极慢"的假象。
3. **捕获区域锁死为模型输入尺寸**：模型按该尺度训练，其他尺寸尺度失配。
4. **推理中锁定模型/显示器/捕获方式**：涉及捕获与会话生命周期竞态。
5. **TRT 加载期间禁用并发枚举**：`EnumDisplaySettingsW`/`EnumDisplayMonitors` 与 NVIDIA 运行库加载存在竞态（曾致 0xC0000005），故刷新率与显示器列表在单线程阶段提前查询缓存。
6. **换模型/加载完成后 `gc.freeze()`**：即使 GC 禁用也保留（万一手动 collect，存量原生对象在永久代不被遍历）。
7. **模型就绪后 `gc.freeze() + gc.enable()` 已废弃**：见决策 1，GC 不再 enable。
8. **窗口隐形为默认行为，无用户配置项**：任务栏隐藏 + Tab/Home 显隐切换均为固定行为。cv2 窗口必须在其首次 `imshow` 显示前改好 `WS_EX_TOOLWINDOW` 样式，任务栏按钮才完全不会闪现；预览窗口隐藏时必须跳过 `imshow`（其内部 `ShowWindow(SW_SHOW)` 会顶掉隐藏状态）。
9. **cv2 窗口标题是 ANSI 乱码**：OpenCV HighGUI 把 UTF-8 标题字节经 ANSI API 传给 Win32，真实标题是 GBK 乱码（"瀹炴椂..."），`FindWindowW` 永远匹配不上——`find_window` 用 `FindWindowA`+UTF-8 原始字节兜底。此 bug 曾导致防截屏对预览窗口一直静默失效。
10. **预览回读限频 60Hz**：readback 的 `CopyResource`+`Map` 会强制 GPU 同步，逐帧回读会在热循环里叠加同步开销；发布率即预览有效帧率（单层节流语义），60fps 足够流畅。
